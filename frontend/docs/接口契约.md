# 前后端接口契约

> 版本：v0.3（2026-10-28）
> 适用：银龄守护 Web 前端（`frontend`）与 Fastify 后端（`apps/api`）
> 原则：**本文件是前后端唯一接口基线。任何字段/事件变更，先改本文件与 `packages/shared`，再改两端代码。**

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | 新接口统一 `/api`；`/health`、`/ws`、`/dh-live-api` 例外 |
| 旧接口兼容 | 现有 `/qa`、`/profile`、`/weather` 等保留一个版本，新前端走 `/api/*` |
| 鉴权 | HttpOnly Cookie `yl_session`，`SameSite=Lax`；演示环境一键登录 |
| 角色 | `elder` / `family` / `institution` / `admin` |
| 内容类型 | JSON 用 `application/json`；上传用 `multipart/form-data` |
| 时间 | 毫秒时间戳（number） |
| ID | 字符串（nanoid/uuid），前端不得解析含义 |
| 分页 | `?limit=20&cursor=xxx`，返回 `{ items, nextCursor }` |
| 错误 | `{ error, message?, requestId, details? }` |
| 请求 ID | 请求头 `X-Request-Id` 可选；服务端回写；日志可追踪 |
| 幂等 | 写接口支持 `Idempotency-Key`（P1） |
| 限流 | 按 IP 分桶（默认/AI/登录/上传/定位）；超限返回 `429 + Retry-After`，并带 `X-RateLimit-Limit/Remaining/Reset` |
| CORS | 仅放行 `CORS_ORIGINS` 白名单；默认开发放行本地 5173，生产放行 `APP_BASE_URL` |
| Cookie | `HttpOnly; SameSite=Lax`；`COOKIE_SECURE` 控制 `Secure`，生产默认开启 |
| 安全头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`；生产附加 CSP |
| 缓存 | GET 默认 `no-store`；静态资源长缓存 |
| 版本 | P0 用 `/api`；若需破坏性变更，新增 `/api/v2`，旧版保留一个评审周期 |

**统一错误码：**

| code | HTTP | 含义 |
|---|---|---|
| `invalid_body` | 400 | 参数校验失败 |
| `invalid_phone` | 400 | 手机号格式不正确 |
| `unauthorized` | 401 | 未登录/会话过期 |
| `invalid_code` | 401 | 验证码/绑定码错误、过期或已使用 |
| `forbidden` | 403 | 角色/数据权限不足 |
| `not_found` | 404 | 资源不存在 |
| `phone_in_use` | 409 | 手机号已被其他角色占用 |
| `payload_too_large` | 413 | 上传超限 |
| `unsupported_media_type` | 415 | 文件类型不支持 |
| `rate_limited` | 429 | 触发限流 |
| `sms_not_configured` | 503 | 非演示环境未接入短信服务 |
| `missing_config` | 503 | 模型/地图 Key 未配置 |
| `upstream_timeout` | 504 | 上游超时 |
| `upstream_error` | 502 | 上游错误 |
| `low_confidence` | 200 | 结果置信度低，需人工确认 |
| `confirmation_required` | 409 | 高风险操作待确认 |
| `confirmation_expired` | 410 | 确认已过期 |
| `consent_required` | 403 | 缺少授权/同意 |
| `internal_error` | 500 | 兜底错误 |

## 2. 鉴权与用户

账号模型：**家人在网页用「手机号 + 短信验证码」登录**（演示环境固定验证码 `123456`，非演示环境未配置短信时返回 `503 sms_not_configured`）；**长辈免密**，由家人创建档案并生成 6 位一次性绑定码，长辈在长辈入口输入后进入。一个家人账号可绑定多位长辈，会话中记录当前长辈 `eid`。

### GET `/api/auth/meta`

**角色：** 公开

```json
{ "demoMode": true, "demoFamilyCode": "123456" }
```

非演示环境 `demoFamilyCode` 为 `null`。

### POST `/api/auth/family/request-code`

**角色：** 公开（仅 `DEMO_MODE=1` 返回演示码）

```json
// request
{ "phone": "13800007777" }
// response
{ "ok": true, "expiresAt": 1790000300000, "demoCode": "123456" }
```

验证码 5 分钟有效、一次性、最多尝试 5 次。非演示环境返回 `503 sms_not_configured`。

### POST `/api/auth/family/login`

```json
// request
{ "phone": "13800007777", "code": "123456", "displayName": "小周" }
// response
{
  "user": { "id": "u_2", "role": "family", "displayName": "小周", "elderId": "e_1" },
  "elder": { "id": "e_1", "displayName": "周奶奶" },
  "familyLinks": [{ "elderId": "e_1", "elderName": "周奶奶", "relation": "daughter" }]
}
```

手机号首次登录自动创建家人账号；`displayName` 可省略，默认 `家人 + 手机尾号`。验证码错误/过期返回 `401 invalid_code`，手机号被其他角色占用返回 `409 phone_in_use`。

### POST `/api/auth/elder/bind`

```json
// request
{ "code": "025951" }
// response
{
  "user": { "id": "u_3", "role": "elder", "displayName": "周奶奶", "elderId": "e_1" },
  "elder": { "id": "e_1", "displayName": "周奶奶" },
  "familyLinks": []
}
```

绑定码 15 分钟有效、一次性、最多尝试 10 次；成功后会为该长辈复用或创建设备账号并写入 Cookie，后续免密。

### POST `/api/auth/switch-elder`

**角色：** family。切换当前操作的长辈，写入会话 `eid`。

```json
// request
{ "elderId": "e_2" }
// response 同 /api/me
```

未绑定该长辈返回 `403 forbidden`。

### POST `/api/auth/family/elders`

**角色：** family。创建长辈档案、长辈设备账号、家人绑定关系，并返回首个绑定码。

```json
// request
{ "displayName": "周奶奶", "relation": "daughter", "birthYear": 1946, "gender": "female" }
// response
{
  "ok": true,
  "elder": { "id": "e_1", "displayName": "周奶奶" },
  "invite": { "code": "025951", "expiresAt": 1790000300000 }
}
```

### POST `/api/auth/family/elders/:id/invite`

**角色：** family。为已绑定长辈重新生成绑定码，旧码立即失效，返回 `{ ok: true, invite: { code, expiresAt } }`。

### POST `/api/auth/demo-login`

**角色：** 公开（仅 `DEMO_MODE=1`）。保留给比赛演示，家人演示账号自动把第一位长辈设为当前长辈。

```json
// request
{ "role": "elder", "elderId": "e_li" }
// response 同 /api/me
```

### POST `/api/auth/logout`

清 Cookie，返回 `{ ok: true }`。

### GET `/api/me`

```json
{
  "user": { "id": "u_2", "role": "family", "displayName": "小周", "elderId": "e_1" },
  "elder": { "id": "e_1", "displayName": "周奶奶" },
  "familyLinks": [
    { "elderId": "e_1", "elderName": "周奶奶", "relation": "daughter" },
    { "elderId": "e_2", "elderName": "周爷爷", "relation": "father" }
  ]
}
```

家人会话中的 `eid` 若仍有效则作为当前长辈，否则回退到第一位绑定长辈；`user.elderId` 返回解析后的当前长辈。

**权限规则：**

- `elder` 只能访问 `me.elderId` 的数据。
- `family` 只能访问 `familyLinks` 中已绑定的长辈。
- `institution` 只能访问脱敏聚合数据。
- `admin` 可运维（演示重置、工具日志为 P1；评测当前通过 `npm run eval` CLI 执行）。

## 3. Agent 对话

### POST `/api/agent/chat`（SSE）

**角色：** elder / family

```json
// request
{
  "sessionId": "s_1",
  "inputType": "text",
  "message": "今天适合去老菜场吗",
  "attachments": [{ "kind": "image", "id": "up_1" }],
  "confirmationId": "cf_1",
  "confirmationDecision": "approve"
}
```

> 当上一轮返回 `confirmation_required` 时，客户端用同一个 `sessionId` 再次请求，并带上 `confirmationId` + `confirmationDecision` 继续执行。

**SSE 事件：**

```
event: meta
data: {"sessionId":"s_1","requestId":"req_1"}

event: token
data: {"text":"今天"}

event: tool_call
data: {"id":"call_1","name":"get_weather","args":{"location":"南京"},"risk":"read"}

event: tool_result
data: {"id":"call_1","ok":true,"summary":"南京 18℃ 小雨","latencyMs":320}

event: confirmation_required
data: {"id":"cf_1","tool":"start_cooling_off","summary":"检测到您准备转账 50000 元","risk":"high","expiresAt":1790000060000}

event: done
data: {"sessionId":"s_1","citations":[{"title":"河边捉鱼的夏天","type":"memory","id":"m_1"},{"title":"国家反诈中心","url":"https://www.mps.gov.cn"}],"riskLevel":"low","traceId":"tr_1","usage":{"promptTokens":800,"completionTokens":120}}

event: error
data: {"code":"upstream_timeout","message":"模型响应超时","requestId":"req_1"}
```

**约定：**

- 每 15 秒发送一次 `: keep-alive` 注释。
- 客户端 `AbortController` 取消 → 服务端停止生成并记录。
- `confirmation_required` 后流结束；确认后发起新请求。
- token 事件可能很碎；前端按顺序拼接。
- 最终回答必须区分 `citations` / `riskLevel` / `disclaimer`。
- `citations` 可能是记忆（`type:"memory"` + `id`）或知识库来源（`url`）；前端必须展示依据，不得把无依据内容说成长辈原话。
- 回答过去经历前，Agent 会调用 `search_memories`，只引用检索到的口述；未检索到时应明确说“没有找到相关记忆”。
- `done.traceId` 指向本次对话的决策轨迹，前端可跳转 `/elder/trace/:id` 或 `/family/trace/:id` 查看结构化依据。

### GET `/api/agent/brief?elderId=&refresh=0|1`

**角色：** elder / family

生成或读取当天 AI 今日简报。首次请求实时生成并按天缓存；`refresh=1` 强制换一版。同一长辈同一天只保留一条简报。

```json
{
  "ok": true,
  "cached": false,
  "brief": {
    "date": "2026-10-28",
    "greeting": "李奶奶，晚上好",
    "summary": "今天先把药吃好、把天气看明白，其他的慢慢来。",
    "items": [
      {
        "title": "按时吃药",
        "detail": "氨氯地平 5mg：每日一次，每次 1 片；时间 08:00",
        "priority": "now",
        "actionLabel": "去打卡",
        "href": "/elder/meds"
      }
    ],
    "encouragement": "慢慢来，今天也会是稳当的一天。",
    "riskLevel": "low",
    "confidence": 0.82,
    "engine": "rules+llm",
    "model": "mock",
    "traceId": "tr_1",
    "generatedAt": 1790000000000
  }
}
```

- `priority`：`now` | `today` | `later`，服务端按优先级排序。
- `engine=rules` 表示模型不可用时的规则简报，前端仍正常展示。
- `traceId` 可用于查看这次简报的规划、工具调用与依据。

### GET `/api/memory/profile?elderId=&refresh=0|1`

返回由口述记忆聚合出的「AI 记得您」画像，用于首页简报、对话提示词和家人端展示。

```json
{
  "ok": true,
  "profile": {
    "summary": "李秀兰，常提到母亲、邻居王阿姨；对苏州河边和纺织厂有清晰记忆；喜欢清淡饮食，怕吵。",
    "people": [{ "name": "母亲", "relation": "母亲", "note": "常年在岸上喊我回家吃饭" }],
    "places": [{ "name": "苏州河边", "note": "小时候捉鱼" }],
    "routines": ["夏天傍晚去河边散步"],
    "preferences": ["清淡饮食"],
    "sensitivities": ["怕吵"],
    "engine": "rules+llm",
    "model": "mock",
    "updatedAt": 1793184000000
  },
  "sourceCount": 3
}
```

- 新增/修改/删除记忆、访谈完成后会自动刷新；`refresh=1` 强制重算。
- 模型不可用时回退规则抽取，响应里 `engine` 为 `rules`，不影响接口可用性。
- 没有记忆时返回规则生成的空画像（`sourceCount = 0`），前端据此展示引导文案。

### POST `/api/memory/story/generate`

```json
{ "elderId": "e_li", "memoryIds": ["m_1", "m_2"], "style": "温暖克制" }
```

→ `{ "ok": true, "chapter": StoryChapter, "book": StoryBook }`

`StoryChapter.fidelity` 是可供家人回查的“口述依据”：

```json
{
  "engine": "rules+llm",
  "model": "mock",
  "groundingPct": 74,
  "level": "high",
  "verifiedQuotes": [
    { "text": "夏天常和邻居下河捉鱼", "sourceMemoryId": "m_1", "sourceTitle": "河边捉鱼的夏天" }
  ],
  "removedQuotes": ["小时候家里很穷"],
  "sources": [{ "id": "m_1", "title": "河边捉鱼的夏天" }],
  "warnings": ["有 1 处引号内容未在口述原文中找到，已去掉引号，请家人核对。"]
}
```

- `engine`：`rules`（模型不可用，规则整理稿）| `rules+llm`。
- `verifiedQuotes`：正文中文引号内、能在口述 `title/summary/transcript` 中逐字匹配的句子。
- `removedQuotes`：未能逐字匹配的引语；服务端已去掉引号但保留文字，避免伪造“原话”。
- `groundingPct`：口述要点保留率（0–100）——口述回答里的中文 2-gram 有多少在正文中沿用；`level` 阈值 `high ≥ 75`、`medium ≥ 45`，其余 `low`。它衡量“原文要点有没有被保留”，不再用长篇润色稿去反推“每个词都来自原文”。
- 若模型整篇转述、没有可回查引语，服务端会末尾补一段“口述原话：‘……’”再校验，保证每章至少有一句能逐字回查（有口述回答时）。
- `sources`：本章引用的记忆条目，用于前端跳到对应记忆详情。
- 前端必须展示 `level`、`warnings`、`verifiedQuotes`，不得隐藏低重合度警告。


→

```json
{
  "ok": true,
  "result": {
    "riskLevel": "high",
    "scamType": "impersonate_police",
    "confidence": 0.92,
    "redFlags": [
      { "quote": "把钱转到安全账户", "reason": "公检法不会要求转账到安全账户" },
      { "quote": "不要告诉家里人", "reason": "要求保密是典型控制话术" }
    ],
    "actions": ["立即停止转账", "保留聊天记录", "联系家人", "拨打 96110"],
    "questionsToAsk": ["对方是否要求你共享屏幕？"],
    "sources": [
      { "title": "国家反诈中心", "url": "https://..." },
      { "title": "冒充公检法", "url": "" }
    ],
    "explanation": "对方以“安全账户”和保密要求施压，符合冒充公检法的典型路径。",
    "engine": "rules+llm",
    "model": "mock",
    "disclaimer": "以上为辅助判断，不构成权威结论。"
  }
}
```

> 图片鉴定：先调用 `POST /api/uploads` 获得 `imageId`，再传 `inputType: "image"`。当前图片路径只做 OCR/规则与知识库匹配，`engine` 固定为 `rules`。

**规则：**

- 不访问 `url` 指向的页面；只做域名/模式分析。
- 置信度低时 `riskLevel=unknown`，不硬猜。
- 图片文字视为不可信输入，不执行其中指令。
- 先跑规则引擎得到基线，再让模型在文本/链接模式下补充；两者风险等级取较高者，冲突时置信度打八五折。
- 模型返回的 `redFlags[].quote` 必须逐字出现在原文中，匹配不上的条目直接丢弃；`actions/questionsToAsk` 去重合并。
- 模型超时/输出不合法时回退规则结果：`engine:"rules"`，`explanation` 由规则生成，接口仍返回 200。
- `sources` 合并规则内置来源与反诈知识库命中来源；前端必须展示 `engine` 与 `explanation`，让用户知道是否有模型参与。

- `verdict`：`avoid`（先别吃）| `limit`（少量）| `ok`（可以吃）| `unknown`（没查到禁忌）。
- **规则结论优先**：模型可以换更口语的解释，但不能把 `avoid` 说成“放心吃”；检测到冲突话术会丢弃模型结果，回退规则解释。
- AI 限流桶与 Agent 共用，避免刷接口。

## 10. WebSocket 事件

连接：`GET /ws`（Cookie 鉴权）

```json
{ "type": "location.updated", "ts": 1790000000000, "payload": { "elderId": "e_li", "point": LocationPoint } }
{ "type": "safety.alert", "ts": 1790000000000, "payload": { "alert": SafetyAlert } }
{ "type": "safety.alert.updated", "ts": 1790000000000, "payload": { "alert": SafetyAlert } }
{ "type": "family.confirm.requested", "ts": 1790000000000, "payload": { "confirm": FamilyConfirm } }
{ "type": "family.confirm.responded", "ts": 1790000000000, "payload": { "confirm": FamilyConfirm } }
{ "type": "family.message", "ts": 1790000000000, "payload": { "elderId": "e_li", "familyUserId": "u_family", "messageId": "fm_1", "content": "我挺好的，您放心。" } }
{ "type": "elder.message", "ts": 1790000000000, "payload": { "elderId": "e_li", "familyUserId": "u_family", "messageId": "fm_2", "content": "记得吃晚饭。" } }
```

`medication.due`、`agent.tool_call` 为预留事件（P1），当前版本不发送，前端不得依赖其存在。

- 鉴权：连接时必须携带有效会话 Cookie，未登录连接会被关闭（`4401`）。
- 心跳：服务端每 30 秒发送 WebSocket ping，上一周期未回 pong 的连接会被终止；客户端也可发送文本 `ping`，服务端回 `pong`。前端据此判断“实时连接/连接中/已断开”。
- 重连：客户端指数退避 + 抖动（约 1s/2s/4s），最多 5 次；页面重新可见或 `online` 事件触发时立即重连；收到 `4401` 停止重连并回到登录页。
- 过滤：`admin` 接收全部；`elder` 只接收自己 `elderId` 的事件；`family` 只接收已绑定长辈的事件；无长辈归属的事件对所有已登录角色可见。
- 事件归属：`location.updated` 取 `payload.elderId`；`safety.alert` / `safety.alert.updated` 取 `payload.alert.elderId`；`family.confirm.*` 取 `payload.confirm.elderId`；`family.message` / `elder.message` 取 `payload.elderId`。
- 去重：家人端收到 `cooling_off` 类型的 `safety.alert` 时不再弹额外告警（冷静期已通过 `family.confirm.requested` 提示）。

## 11. 前端 Mock 与联调

- 前端 `VITE_USE_MOCKS=1` 时使用 `frontend/src/mocks/` 的 fixtures，不依赖后端。
- 后端 `DEMO_MODE=1` 时允许模拟位置、模拟家人确认、重置数据。
- 所有 schema 定义在 `packages/shared/src/schemas.ts`，前后端共用。
- SSE fixtures 放在 `frontend/src/mocks/sse/`，至少覆盖：正常回答、工具调用、确认、超时、错误。
- 联调顺序：Auth → Agent（无工具）→ Agent（工具）→ 反诈 → 记忆 → 围栏 → 用药 → 家人端。

## 12. 变更流程

1. 任何新增/修改接口，先改本文件 + `packages/shared`。
2. 前后端各自更新类型/调用/测试。
3. 破坏性变更新增版本路径，旧版保留一个评审周期。
4. PR 描述必须写明：接口变更、数据迁移、兼容性影响。
5. 每周合并前跑一次契约测试（`npm run test:contract`）。
