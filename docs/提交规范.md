# 提交信息规范

> 目的：GitHub / Gitee 会直接把提交信息展示给评审和协作者。提交信息要能独立说明「改了什么模块、为什么改、怎么验证」。

## 1. 格式

```text
<type>(<scope>): <中文简述，50 字以内>

背景：

改动：
- 

验证：
- 

影响/备注：
- 
```

- 第一行是标题，不要写句号。
- 简述用祈使句，例如「接入记忆访谈」而不是「接入了记忆访谈」。
- 一个提交只做一件逻辑上的事；不要把无关改动混在一起。
- 正文中的「背景 / 改动 / 验证 / 影响」按需保留，至少写「改动」和「验证」。
- 提交信息中不出现密码、Token、`.env` 内容、真实手机号/住址。

## 2. type

| type | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `docs` | 文档 |
| `refactor` | 不改变行为的重构 |
| `test` | 测试 |
| `perf` | 性能优化 |
| `chore` | 构建/依赖/工具/仓库维护 |
| `build` | 构建系统或依赖变更 |
| `ci` | CI 配置 |

## 3. scope

| scope | 范围 |
|---|---|
| `web` | `apps/web` 前端 |
| `api` | `apps/api` 后端 |
| `shared` | `packages/shared` |
| `docs` | 文档 |
| `repo` | 仓库级配置（忽略规则、模板、脚本） |
| `mcp` | `apps/mcp-server` |
| `deploy` | Docker、Compose、生产托管 |
| `deps` | 依赖升级 |
| `dh-live` | 数字人集成 |

## 4. 示例

### 前端

```text
feat(web): 接入长者首页与 Agent 流式对话

背景：
- 后端已提供 /api/agent/chat SSE，前端仍是旧问答页。

改动：
- 新增角色选择、长者三按钮首页、家属概览
- 新增 Agent 消息流、工具调用卡片、高风险确认弹窗
- 新增 /api、/public、/ws 同源代理，修复 Cookie 鉴权

验证：
- npm run typecheck -w apps/web
- npm run build -w apps/web
- 浏览器实测：登录 → 天气问答 → 转账确认 → 家属拒绝
```

### 后端

```text
feat(api): 接入记忆访谈与反诈知识库检索

背景：
- W2 需要打通长者记忆采集与反诈鉴定主链路。

改动：
- 新增 interviews 表、记忆/故事/上传仓储
- 新增 5 轮访谈状态机、故事章节生成
- 新增 12 条反诈知识库与关键词 + Embedding 混合检索
- 新增冷静期/家属确认接口

验证：
- npm run test -w apps/api（22 个测试）
- 上传图片 → 图片鉴定 → 静态文件 200 冒烟
```

### 修复

```text
fix(api): 对齐冷静期确认窗口与 60 秒倒计时

背景：
- Agent 确认窗默认 5 分钟，与产品定义的 60 秒冷静期不一致。

改动：
- start_cooling_off 的确认 TTL 改为 60 秒
- 故事生成在无模型时改用完整访谈回答

验证：
- npm run test -w apps/api
```

## 5. 模板

仓库根目录提供了 `.gitmessage`。可选启用：

```bash
git config commit.template .gitmessage
```

> 这是个人本地配置，不影响仓库内容；团队自行决定是否启用。

## 6. 已推送历史

已推送到 GitHub 的提交不回写、不强制推送。从启用本规范后的下一次提交开始执行。若确需整理历史，先与团队确认，避免影响评审看到的提交记录。
