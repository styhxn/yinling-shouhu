# 部署与在线演示

生产模式由一个 Fastify 进程同时提供 API、上传文件与前端静态页面，前端路由由服务端回退到 `index.html`。

## 方式一：本地生产预演

```bash
npm ci
npm run build

# 在 apps/api 工作目录下启动（npm workspace 会自动切换）
NODE_ENV=production \
SESSION_SECRET=replace-with-a-long-random-string \
COOKIE_SECURE=0 \
DEMO_MODE=1 \
npm run start -w apps/api
```

打开 <http://127.0.0.1:3100>。若没有配置任何模型 Key，后端会自动使用 Mock 模型，页面仍可完整体验。

> `NODE_ENV=production` 默认给会话 Cookie 加 `Secure`，纯 HTTP 预演会登录失败；本地 HTTP 必须显式 `COOKIE_SECURE=0`，HTTPS 部署则保持默认（或显式设为 `1`）。

上述命令默认使用零配置 SQLite。若想在本机预演 PostgreSQL，先启动数据库并额外设置 `DB_DRIVER=postgres DATABASE_URL=postgres://user:password@127.0.0.1:5432/yinling`（本地无 TLS 时 `DB_SSL=0`）。

前端构建目录默认是 `frontend/dist`（相对仓库根目录），可通过 `WEB_DIST_DIR` 覆盖；上传文件默认写入 `apps/api/public/uploads`，可通过 `PUBLIC_DIR` 覆盖。

## 方式二：Docker Compose（推荐，PostgreSQL + pgvector）

Compose 会同时启动 `db`（`pgvector/pgvector:pg16`）与 `app`。应用以 PostgreSQL 16 + pgvector 作为生产存储，启动时自动建表、启用向量扩展并写入演示数据。

```bash
# 复制模板并在根目录 .env 中修改 SESSION_SECRET 与 POSTGRES_PASSWORD
cp .env.example .env
docker compose up -d --build
docker compose logs -f app
```

- 访问地址：<http://服务器IP:3100>
- `app` 通过 `depends_on` 等待 `db` 的 `pg_isready` 健康检查通过后再启动
- 数据卷：`pg-data`（PostgreSQL 数据）、`app-data`（主密钥与本地数据）、`app-public`（上传图片）
- 健康检查：`GET /health`；就绪检查：`GET /ready`（返回 `dbDriver` 与 `vector` 状态）

> 演示环境默认 `DEMO_MODE=1`。正式环境请删除该变量，并接入真实登录。
>
> Compose 默认 `COOKIE_SECURE=0`，以便直接通过 `http://服务器IP:3100` 演示；启用 HTTPS 后必须改为 `COOKIE_SECURE=1`，否则 Cookie 不设 `Secure`。反向代理部署同时设置 `TRUST_PROXY=1`。
>
> `POSTGRES_PASSWORD` 默认值仅用于本地试跑，公网部署必须替换为强密码；`DATABASE_URL` 不要提交到仓库。

## 数据库初始化

同一套仓储代码支持两种存储，按环境切换，不需要改业务代码：

| 场景 | 驱动 | 说明 |
| --- | --- | --- |
| 本地开发 / 离线演示 | `DB_DRIVER=sqlite`（默认） | 零配置单文件 `$DATA_DIR/app.db`，无需安装数据库 |
| 生产 / 答辩演示 | `DB_DRIVER=postgres` | PostgreSQL 16 + pgvector；Compose 已内置 `pgvector/pgvector:pg16` |

- 后端启动时自动执行 `apps/api/src/store/migrations.ts` 建表，语句幂等；`DEMO_MODE=1` 时还会写入李奶奶等演示数据。
- PostgreSQL 模式会自动执行 `CREATE EXTENSION IF NOT EXISTS vector` 并维护 `embeddings` 表；向量检索使用 pgvector 余弦距离，扩展不可用时自动回退到内存关键词/余弦打分，接口不报错。
- 就绪检查：`GET /health`（进程存活）、`GET /ready`（数据库 ping + 向量索引状态）。

### SQLite（本地 / 离线）

- 数据库文件：`$DATA_DIR/app.db`，默认 `apps/api/data/app.db`；主密钥在同目录的 `master.key`。
- Docker 部署时，`app-data` 卷挂载到 `/app/data`。
- 需要手工初始化或给 DBA 审计时，可使用 [schema.sql](schema.sql)（由迁移代码生成，**33 张表 + 21 个索引**）：

```bash
# 服务器需要安装 sqlite3 CLI；也可以在本地执行后上传 app.db
sqlite3 /path/to/app.db < docs/schema.sql
```

### PostgreSQL（生产 / 答辩）

- 连接串格式：`postgres://user:password@host:5432/dbname`，写入 `DATABASE_URL` 并设置 `DB_DRIVER=postgres`。
- 数据库只需提前创建，表、索引、扩展都由应用启动时自动创建；也可让 DBA 预执行 [schema.postgres.sql](schema.postgres.sql)（**34 张表（含 `schema_migrations`）+ 21 个索引**，含 `vector` 扩展与 `embeddings.embedding` 列）。
- Compose 中库名/用户/密码由 `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` 控制，应用连接串自动拼接。

```bash
# 可选：手工预建（需要本机安装 psql 与 pgvector）
psql "$DATABASE_URL" -f docs/schema.postgres.sql
```

- 脚本只建表，不写演示数据，可重复执行。
- 修改表结构时，先改 `migrations.ts`，再运行 `npm run db:schema`，会同时重新生成 `docs/schema.sql` 与 `docs/schema.postgres.sql`，不要手改生成物。
- **不支持 MySQL**：仓储层提供 SQLite / PostgreSQL 两套 `SqlClient` 驱动；如需 MySQL，要新增驱动实现并重做迁移脚本，不能只执行一份 DDL。

### 备份

| 存储 | 备份对象 | 命令 |
| --- | --- | --- |
| SQLite | `app.db` + `master.key` | `sqlite3 app.db ".backup backup.db"` |
| PostgreSQL | `pg-data` 卷快照或逻辑备份 + `master.key` | `docker compose exec db pg_dump -U yinling yinling > backup.sql` |

`master.key`（或 `MASTER_KEY`）必须与数据库一起备份，否则加密字段（记忆、位置、联系方式等）无法解密。SQLite 开启 WAL，备份前建议先停止服务或使用 `.backup` 命令。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `NODE_ENV` | `development` | 设为 `production` 后启用前端静态托管与 SPA 回退 |
| `PORT` / `HOST` | `3100` / `127.0.0.1` | 容器内请设为 `0.0.0.0` |
| `SESSION_SECRET` | 开发默认值 | **生产必填**，用于 HMAC 会话签名 |
| `DEMO_MODE` | 关闭 | `1` 时开放演示账号与种子数据 |
| `DB_DRIVER` | 未设 `DATABASE_URL` 时 `sqlite` | `sqlite` 或 `postgres`；设置 `DATABASE_URL` 会自动切换为 `postgres` |
| `DATABASE_URL` | 空 | PostgreSQL 连接串；`DB_DRIVER=postgres` 时必填 |
| `DB_POOL_MAX` | `10` | PostgreSQL 连接池上限 |
| `DB_SSL` | `0` | 云数据库要求 SSL 时设 `1` |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | `yinling` / `yinling` / `change-this-password` | Compose 的 `db` 服务使用；公网部署必须改密码 |
| `DATA_DIR` | `./data` | SQLite 数据库与 `master.key` |
| `PUBLIC_DIR` | `./public` | 上传文件根目录 |
| `WEB_DIST_DIR` | `../../frontend/dist` | 前端构建产物目录（相对 `apps/api`） |
| `APP_BASE_URL` | `http://localhost:5173` | 对外访问地址，用于海报等链接与默认 CORS 源 |
| `COOKIE_SECURE` | 生产自动 `1` | 会话 Cookie 是否加 `Secure`；本地 HTTP 预演必须设 `0` |
| `CORS_ORIGINS` | 空 | 允许的前端源，逗号分隔；留空时开发放行本地 5173，生产放行 `APP_BASE_URL` |
| `TRUST_PROXY` | `0` | Nginx/Caddy 后设 `1`，用于按真实客户端 IP 限流 |
| `RATE_LIMIT_ENABLED` | `1` | 限流总开关；压测或演示可设 `0`，上线保持开启 |
| `RATE_LIMIT_WINDOW_MS` | `60000` | 限流窗口 |
| `RATE_LIMIT_MAX` / `RATE_LIMIT_AUTH_MAX` / `RATE_LIMIT_AI_MAX` / `RATE_LIMIT_UPLOAD_MAX` / `RATE_LIMIT_LOCATION_MAX` | `300` / `20` / `40` / `20` / `120` | 默认、登录、AI、上传、定位五个桶的单窗口上限 |
| `RETENTION_LOCATION_DAYS` / `RETENTION_TOOL_LOG_DAYS` / `RETENTION_AUDIT_DAYS` / `RETENTION_ALERT_DAYS` / `RETENTION_POSTER_DAYS` | `90` / `30` / `180` / `180` / `7` | 位置、工具日志、审计日志、已处理告警、过期海报的保留天数；启动与每日清理 |
| `LLM_MOCK` | 自动 | `1` 强制 Mock；无任何模型 Key 时也会自动 Mock |
| `DEEPSEEK_API_KEY` / `QWEN_API_KEY` / `ARK_API_KEY` | 空 | 任选其一即可启用真实模型 |
| `AMAP_WEB_KEY` | 空 | 高德 Web 服务 Key；留空时天气返回演示数据 |
| `LLM_TIMEOUT_MS` | `20000` | 单次模型调用超时 |

完整变量见 [apps/api/.env.example](../apps/api/.env.example)。

## 评测与验收

```bash
npm run verify          # 类型检查 + 构建 + 全部测试
npm run eval            # 反诈/故事/Agent 评测集，默认 Mock 模型
npm run eval -- --module=agent --json
```

- 评测会写入 `eval_cases` / `eval_runs`，退出码 `0` 表示达到 `EVAL_MIN_PASS`（默认 80）。
- 接入真实模型后重新跑一次，记录模型名与指标；指标定义和 Mock 基线（15/15）见 [评测报告](评测报告.md)。
- AI 今日简报按“长辈 + 日期”缓存于 `agent_briefs`，`refresh=1` 可强制重算；决策轨迹写入 `agent_traces`，默认随工具日志按 `RETENTION_TOOL_LOG_DAYS` 清理。
- 告警落库后由守护 Agent 异步研判并写回 `payload.assessment`；单进程内存去重，重启后会对未处理告警做一次补判。
- 演示前建议按顺序走一遍：登录 → AI 今日简报 → 对话（含记忆引用与轨迹）→ 反诈鉴定 → 角色演练 → 记忆访谈/故事依据 → 定位与围栏告警（看守护 Agent 研判）→ 家属简报与告警轨迹。

## 反向代理（可选）

生产环境建议在 Nginx / Caddy 后启用 HTTPS。SSE 与 WebSocket 需要关闭缓冲并支持升级。

```nginx
server {
  listen 443 ssl http2;
  server_name example.com;

  location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location /api/agent/chat {
    proxy_pass http://127.0.0.1:3100;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
    add_header X-Accel-Buffering no;
  }

  location /ws {
    proxy_pass http://127.0.0.1:3100;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 300s;
  }
}
```

设置 `APP_BASE_URL=https://example.com`、`TRUST_PROXY=1`、`COOKIE_SECURE=1`，并确保 `SESSION_SECRET` 足够长且只保存在服务器环境变量中。服务端每 30 秒发送 WebSocket ping，代理的 `proxy_read_timeout` 不应低于该值。

## 数据卷与上传文件

- 上传文件：`$PUBLIC_DIR/uploads/`，Compose 中挂载到 `app-public` 卷。
- `app-data`：主密钥与本地 SQLite 数据；`pg-data`：PostgreSQL 数据目录。
- 升级镜像前先备份 `pg-data`（或执行 `pg_dump`）与 `app-data`；`docker compose down` 不会删除具名卷，`docker compose down -v` 会删除全部数据卷，务必确认后再执行。

## 数字人（可选）

DH_live 数字人服务是独立的 Python 进程，不包含在本镜像内。未启动时，前端会使用浏览器语音与静态头像，不影响其他功能。需要展示数字人时：

1. 按 DH_live 文档启动其 Web 服务；
2. 通过 Nginx 将 `/dh-live-api/` 与 `/dh-live-static/` 转发到该服务；
3. 或仅在演示机本地运行 DH_live，生产环境使用默认降级方案。
