# 部署与在线演示

生产模式由一个 Fastify 进程同时提供 API、上传文件与前端静态页面，前端路由由服务端回退到 `index.html`。生产数据库为 **MySQL 8**，本地开发仍可使用零配置的 SQLite。

## 方式一：一键部署（systemd + MySQL，推荐）

适用于 Alibaba Cloud Linux 3 / RHEL 8+ / Debian 12+ 的云服务器。要求 root 执行、能访问外网（安装 Node 与 npm 依赖）。

```bash
git clone https://github.com/styhxn/yinling-shouhu.git
cd yinling-shouhu
bash deploy.sh
bash deploy.sh ai   # 可选：配置真实 Qwen 模型
```

脚本会依次完成：

1. 检查系统、内存、磁盘与端口；内存不足 2GB 且无 swap 时自动创建 2GB swap（构建前端需要）；
2. 安装基础依赖；若 Node 低于 22.5 或位于 `/root`、`/home` 等 systemd 无法访问的目录，安装 Node 24 到 `/usr/local`；
3. 安装并启动 MySQL 8（已有则跳过），创建数据库与应用账号；已有 MySQL 的 root 有密码时，会在终端提示输入（输入不回显，也不会写入配置文件）；脚本新建的 MySQL 会限制监听 `127.0.0.1`，已有实例请自行确认 `bind-address`；
4. 生成 `/etc/yinling/yinling.env`（权限 600），自动生成 `SESSION_SECRET`、`MASTER_KEY`、`MYSQL_PASSWORD`，并推断公网访问地址（优先公网 IP 探测，阿里云 ECS 会读取元数据；若配置里已是内网 IP 会自动纠正）；
5. 已有服务在运行时，先备份 MySQL、数据目录与配置文件到 `/var/backups/yinling/`（保留最近 5 份）；
6. 安装 npm 依赖并构建共享包、API 与前端；
7. 写入并启动 `yinling.service`，轮询 `/ready` 成功后输出访问地址；
8. 检查数据库迁移（含 W8 的 `health_profiles` 表），并显示 AI 是 `live` 还是 `mock`；
9. 启动失败时打印 systemd 状态与最近 120 行日志。

```bash
bash deploy.sh --help    # 查看全部命令
bash deploy.sh check     # 只做环境检查，不修改系统
bash deploy.sh status    # systemd 状态 + /ready
bash deploy.sh logs      # 跟踪应用日志
bash deploy.sh backup    # 立即备份
bash deploy.sh restart   # 重启并等待就绪
bash deploy.sh stop      # 停止应用（MySQL 与数据保留）
bash deploy.sh ai        # 交互式写入 Qwen Key/网关/模型并重启
bash deploy.sh --no-build   # 跳过依赖安装与构建，直接用现有 dist 重启
```

### 上传新版本后如何更新

本机先生成干净源码包（自动排除 `node_modules`、`.env`、`.backup`、`.shots`、本地 SQLite 数据与上传文件）：

```bash
bash deploy.sh pack
# 输出：../yinling-shouhu-src-<时间>.tar.gz
```

把 tar.gz 上传到服务器，解压到任意目录（不要直接覆盖正在运行的 `/opt/yinling-shouhu`），进入解压后的目录执行：

```bash
mkdir -p yinling-new
tar -xzf yinling-shouhu-src-*.tar.gz -C yinling-new
cd yinling-new
bash deploy.sh
```

脚本会自动：

1. 备份 MySQL、`/var/lib/yinling` 与 `/etc/yinling/yinling.env`；
2. 保留现有端口、数据库密码、`MASTER_KEY`、模型 Key 和上传文件；
3. 同步新代码到 `/opt/yinling-shouhu`、执行 `npm ci`、构建前端与 API；
4. 启动服务时自动执行幂等迁移（新增 `health_profiles` 等表，不会清空旧数据）；
5. 等待 `/ready`，然后打印访问地址和 AI 状态。

> 更新时不要删除 `/etc/yinling/yinling.env` 和 `/var/lib/yinling`。`MASTER_KEY` 一旦丢失，历史加密数据无法解密。

### 配置真实模型（推荐）

首次部署后执行：

```bash
bash deploy.sh ai
```

按提示输入 `QWEN_API_KEY`，网关默认 `https://moma.cmecloud.cn/v1`，模型默认 `qwen/qwen3.5-plus`；直接回车使用默认值。Key 只写入 `/etc/yinling/yinling.env`（600），不会出现在仓库或日志中。也可以用非交互方式：

```bash
QWEN_API_KEY='...' \
QWEN_BASE_URL='https://moma.cmecloud.cn/v1' \
QWEN_MODEL='qwen/qwen3.5-plus' \
bash deploy.sh ai
```

配置完成后 `/ready` 应显示 `"llm":"live"`；如果是 `mock`，说明 Key 或网关未生效，执行 `bash deploy.sh logs` 查看原因。

部署后的固定位置：

| 内容 | 路径 |
| --- | --- |
| 代码与构建产物 | `/opt/yinling-shouhu`（可用 `INSTALL_DIR` 覆盖） |
| 环境配置（含密钥） | `/etc/yinling/yinling.env` |
| 数据（主密钥、上传文件） | `/var/lib/yinling`（`data/`、`public/`） |
| systemd 服务 | `/etc/systemd/system/yinling.service` |
| 备份 | `/var/backups/yinling/<时间戳>/` |

> 默认 `APP_PORT=3200`，避免与同机已有的 3100 服务冲突。改端口需编辑 `/etc/yinling/yinling.env` 的 `APP_PORT` 后重新执行 `bash deploy.sh`。
>
> **阿里云安全组必须放行 TCP 3200**（或实际使用的端口），否则公网无法访问；服务器内 firewalld 若在运行，脚本会自动放行。
>
> 首次生成的访问地址是 `http://服务器IP:3200`。接入域名/HTTPS 后，把 `APP_BASE_URL` 改为 `https://example.com` 再执行 `bash deploy.sh`，脚本会自动把 `COOKIE_SECURE` 与 `TRUST_PROXY` 设为 `1`。反向代理不传 `X-Forwarded-For` 时，把 `TRUST_PROXY` 改回 `0`。

覆盖数据库、端口或模型 Key 时，可在首次执行前通过环境变量传入（显式传入的模型配置会覆盖旧值）：

```bash
APP_PORT=3200 \
MYSQL_PASSWORD='填入强密码' \
QWEN_API_KEY='sk-...' \
QWEN_BASE_URL='https://moma.cmecloud.cn/v1' \
QWEN_MODEL='qwen/qwen3.5-plus' \
bash deploy.sh
```

`MYSQL_PASSWORD` 只允许字母、数字和 `._~-`，因为它会被拼进 `DATABASE_URL`。已有 MySQL 的 root 密码不需要写进命令，脚本会在终端提示输入；只有非交互环境（如 CI）才需要设置 `MYSQL_ROOT_PASSWORD`。

## 方式二：本地生产预演

```bash
npm ci
npm run build

# 在 apps/api 工作目录下启动（npm workspace 会自动切换）
NODE_ENV=production \
SESSION_SECRET=replace-with-a-long-random-string \
COOKIE_SECURE=0 \
DEMO_MODE=1 \
npm run start -w apps/api
```

打开 <http://127.0.0.1:3100>。若没有配置任何模型 Key，后端会自动使用 Mock 模型，页面仍可完整体验。

> `NODE_ENV=production` 默认给会话 Cookie 加 `Secure`，纯 HTTP 预演会登录失败；本地 HTTP 必须显式 `COOKIE_SECURE=0`，HTTPS 部署则保持默认（或显式设为 `1`）。

以上命令默认使用零配置 SQLite。若想在本机预演 MySQL，先启动 MySQL 8 并设置：

```bash
DB_DRIVER=mysql \
DATABASE_URL=mysql://yinling:password@127.0.0.1:3306/yinling \
npm run start -w apps/api
```

前端构建目录默认是 `frontend/dist`（相对仓库根目录），可通过 `WEB_DIST_DIR` 覆盖；上传文件默认写入 `apps/api/public/uploads`，可通过 `PUBLIC_DIR` 覆盖。

## 方式三：Docker Compose（可选）

仓库内仍保留 `docker-compose.yml`，用于本地或已装 Docker 的机器快速拉起 MySQL 8 + 应用：

```bash
cp .env.example .env
# 修改 .env 中的 SESSION_SECRET、MYSQL_PASSWORD、MYSQL_ROOT_PASSWORD
docker compose up -d --build
docker compose logs -f app
```

- 访问地址：<http://服务器IP:3100>
- `db` 使用 `mysql:8.0`，`app` 通过 `depends_on` 等待 `mysqladmin ping` 健康检查通过；
- 数据卷：`mysql-data`（MySQL 数据）、`app-data`（主密钥与本地数据）、`app-public`（上传图片）；
- 健康检查：`GET /health`；就绪检查：`GET /ready`（返回 `dbDriver=mysql`）。

> **不推荐在 2GB 内存的云服务器上使用 Docker**：MySQL 与构建容器会额外占用内存。云服务器请优先使用方式一（宿主机 systemd + MySQL）。

## 数据库初始化

同一套仓储代码支持两种存储，按环境切换，不需要改业务代码：

| 场景 | 驱动 | 说明 |
| --- | --- | --- |
| 本地开发 / 离线演示 | `DB_DRIVER=sqlite`（默认） | 零配置单文件 `$DATA_DIR/app.db`，无需安装数据库 |
| 生产 / 答辩演示 | `DB_DRIVER=mysql` | MySQL 8.0+，`deploy.sh` 自动安装并建库 |

- 后端启动时自动执行 `apps/api/src/store/migrations.ts` 建表，语句幂等；`DEMO_MODE=1` 时还会写入李奶奶等演示数据。
- MySQL 使用连接池（`mysql2`），支持 `DB_POOL_MAX` 与 `DB_SSL`；未使用 pgvector，反诈语义检索在内存中完成，MySQL 无需额外扩展。
- 就绪检查：`GET /health`（进程存活）、`GET /ready`（数据库 ping、`dbDriver`、LLM 模式与 `demoMode`）。

### SQLite（本地 / 离线）

- 数据库文件：`$DATA_DIR/app.db`，默认 `apps/api/data/app.db`；主密钥在同目录的 `master.key`。
- 需要手工初始化或给 DBA 审计时，可使用 [schema.sql](schema.sql)（由迁移代码生成，**36 张表 + 24 个索引**）：

```bash
# 服务器需要安装 sqlite3 CLI；也可以在本地执行后上传 app.db
sqlite3 /path/to/app.db < docs/schema.sql
```

### MySQL（生产 / 答辩）

- 连接串格式：`mysql://user:password@host:3306/dbname`，写入 `DATABASE_URL` 并设置 `DB_DRIVER=mysql`。
- 数据库只需提前创建，表与索引都由应用启动时自动创建；也可让 DBA 预执行 [schema.mysql.sql](schema.mysql.sql)（**37 张表（含 `schema_migrations`）+ 26 个索引**）。
- `deploy.sh` 会在本机安装 MySQL 8，创建 `MYSQL_DATABASE` / `MYSQL_USER`，并将服务限制在 `127.0.0.1`。

```bash
# 可选：手工预建（数据库需已存在）
mysql -u root -p yinling < docs/schema.mysql.sql
```

- 脚本只建表，不写演示数据，可重复执行。
- 修改表结构时，先改 `migrations.ts`，再运行 `npm run db:schema`，会同时重新生成 `docs/schema.sql` 与 `docs/schema.mysql.sql`，不要手改生成物。
- MySQL 保留字冲突已处理（如 `agent_traces.trigger_type`）；从旧版 SQLite 升级时会自动重命名旧列。

## 备份与恢复

| 存储 | 备份对象 | 命令 |
| --- | --- | --- |
| SQLite | `app.db` + `master.key` | `sqlite3 app.db ".backup backup.db"` |
| MySQL | 逻辑备份 + `master.key` + 上传文件 | `mysqldump --single-transaction --no-tablespaces -u USER -p DB > backup.sql` |

`master.key`（或 `MASTER_KEY`）必须与数据库一起备份，否则加密字段（记忆、位置、联系方式等）无法解密。

`deploy.sh` 在升级前自动备份到 `/var/backups/yinling/<时间戳>/`，包含：

- `db.sql.gz`：`mysqldump` 压缩备份；
- `files.tar.gz`：`/var/lib/yinling/data` 与 `public`（含 `master.key` 与上传文件）；
- `code.tar.gz`：更新前的 `/opt/yinling-shouhu` 代码与构建产物（不含 `node_modules`）；
- `env.backup`：`/etc/yinling/yinling.env`（含密钥，注意保管）；
- `README.txt`：恢复步骤。

只保留最近 5 份。也可以手动执行 `bash deploy.sh backup`。

恢复示例：

```bash
systemctl stop yinling
gunzip < db.sql.gz | mysql -h127.0.0.1 -u yinling -p yinling
tar -xzf files.tar.gz -C /var/lib/yinling
cp env.backup /etc/yinling/yinling.env && chmod 600 /etc/yinling/yinling.env
# 需要回滚代码时再执行：
# tar -xzf code.tar.gz -C /opt/yinling-shouhu
systemctl start yinling
```

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `NODE_ENV` | `development` | 设为 `production` 后启用前端静态托管与 SPA 回退 |
| `PORT` / `HOST` | `3200` / `127.0.0.1` | systemd 部署由脚本设为 `0.0.0.0`；本地开发默认 `3100` |
| `SESSION_SECRET` | 开发默认值 | **生产必填**，用于 HMAC 会话签名；脚本自动生成 |
| `DEMO_MODE` | 本地关闭；`deploy.sh` 默认 `1` | `1` 时开放演示账号与种子数据；正式环境改 `0` |
| `DB_DRIVER` | 未设 `DATABASE_URL` 时 `sqlite` | `sqlite` 或 `mysql` |
| `DATABASE_URL` | 空 | MySQL 连接串；`DB_DRIVER=mysql` 时必填 |
| `DB_POOL_MAX` | `10` | MySQL 连接池上限 |
| `DB_SSL` | `0` | 云数据库要求 SSL 时设 `1` |
| `MYSQL_DATABASE` / `MYSQL_USER` / `MYSQL_PASSWORD` | `yinling` / `yinling` / 自动生成 | 一键部署与 Compose 使用；密码只允许字母、数字和 `._~-` |
| `MYSQL_ROOT_PASSWORD` | 空 | 可选；已有 MySQL 的 root 密码，仅用于建库建账号，不写入配置文件；交互终端会直接提示输入 |
| `APP_PORT` | `3200` | 生产对外监听端口；本地开发仍用 `3100` |
| `DATA_DIR` | `./data` | SQLite 数据库、`master.key` 与运行数据 |
| `PUBLIC_DIR` | `./public` | 上传文件根目录 |
| `WEB_DIST_DIR` | `../../frontend/dist` | 前端构建产物目录（相对 `apps/api`） |
| `MASTER_KEY` | 自动生成 | 32 字节 base64，加密敏感字段；必须备份，不能随意更换 |
| `APP_BASE_URL` | `http://localhost:5173` | 对外访问地址，用于海报等链接与默认 CORS 源；脚本会自动探测公网 IP，失败时可手动覆盖 |
| `COOKIE_SECURE` | 生产自动 `1` | 会话 Cookie 是否加 `Secure`；纯 HTTP 部署必须设 `0` |
| `CORS_ORIGINS` | 空 | 允许的前端源，逗号分隔；留空时开发放行本地 5173，生产放行 `APP_BASE_URL` |
| `TRUST_PROXY` | `0` | Nginx/Caddy 后设 `1`，用于按真实客户端 IP 限流 |
| `RATE_LIMIT_ENABLED` | `1` | 限流总开关；压测或演示可设 `0`，上线保持开启 |
| `RATE_LIMIT_WINDOW_MS` | `60000` | 限流窗口 |
| `RATE_LIMIT_MAX` / `RATE_LIMIT_AUTH_MAX` / `RATE_LIMIT_AI_MAX` / `RATE_LIMIT_UPLOAD_MAX` / `RATE_LIMIT_LOCATION_MAX` | `300` / `20` / `40` / `20` / `120` | 默认、登录、AI、上传、定位五个桶的单窗口上限 |
| `RETENTION_LOCATION_DAYS` / `RETENTION_TOOL_LOG_DAYS` / `RETENTION_AUDIT_DAYS` / `RETENTION_ALERT_DAYS` / `RETENTION_POSTER_DAYS` | `90` / `30` / `180` / `180` / `7` | 位置、工具日志、审计日志、已处理告警、过期海报的保留天数；启动与每日清理 |
| `LLM_MOCK` | 自动 | `1` 强制 Mock；无任何模型 Key 时也会自动 Mock |
| `DEEPSEEK_API_KEY` / `QWEN_API_KEY` / `ARK_API_KEY` | 空 | 任选其一即可启用真实模型 |
| `QWEN_BASE_URL` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | Qwen 的 OpenAI 兼容网关；MoMA 用 `https://moma.cmecloud.cn/v1` |
| `QWEN_MODEL` | `qwen-plus` | 文本对话模型；MoMA 用 `qwen/qwen3.5-plus` |
| `QWEN_ENABLE_THINKING` | `0` | 长辈对话关掉思考；开启后首字延迟从 ~1.6s 涨到 ~25s |
| `LLM_VISION_MODEL` / `LLM_EMBED_MODEL` | `qwen/qwen3-vl-plus` / `text-embedding-v3` | 视觉/向量模型需单独订阅；未订阅时药盒拍照、图片反诈会回退规则或提示人工核实 |
| `AMAP_WEB_KEY` | 空 | 高德 Web 服务 Key；留空时天气返回演示数据 |
| `LLM_TIMEOUT_MS` | `20000` | 单次模型调用超时 |

完整变量见 [apps/api/.env.example](../apps/api/.env.example)；一键部署生成的配置在 `/etc/yinling/yinling.env`。

### 生产开启真实模型（不把 Key 写进仓库）

推荐直接执行 `bash deploy.sh ai`（见上文）。如果已有配置文件，也可以手工修改后重启：

```bash
# Key 只存在服务器的 600 权限文件里
nano /etc/yinling/yinling.env
#    LLM_MOCK=0
#    QWEN_API_KEY=<在模型网关控制台创建>
#    QWEN_BASE_URL=https://moma.cmecloud.cn/v1
#    QWEN_MODEL=qwen/qwen3.5-plus
#    QWEN_ENABLE_THINKING=0

systemctl restart yinling
curl -s http://127.0.0.1:3200/ready
```

`/ready` 返回 `"llm":"live"` 即生效；返回 `"llm":"mock"` 说明 Key 或网关未生效。若模型请求返回 `subscription_required`，说明当前 Key 只开通了文本模型，视觉/向量功能会自动降级，不影响聊天和饮食。

> 当前 Qwen 订阅只包含文本对话与函数调用；`qwen3-vl-plus`、`qwen3.5-omni`、`bge-base-zh-v1.5` 等会返回 HTTP 402。药盒拍照、图片反诈、语义检索暂用规则/关键词回退，答辩时如实说明。

## 评测与验收

```bash
npm run verify          # 类型检查 + 构建 + 全部测试
npm run eval            # 反诈/故事/Agent 评测集，跟随 apps/api/.env 的模型配置
npm run eval -- --module=agent --json
```

- 评测会写入 `eval_cases` / `eval_runs`，退出码 `0` 表示达到 `EVAL_MIN_PASS`（默认 80）。
- 接入真实模型后重新跑一次，记录模型名与指标；指标定义和 Mock 基线（15/15）见 [评测报告](评测报告.md)。
- AI 今日简报按“长辈 + 日期”缓存于 `agent_briefs`，`refresh=1` 可强制重算；决策轨迹写入 `agent_traces`，默认随工具日志按 `RETENTION_TOOL_LOG_DAYS` 清理。
- 告警落库后由守护 Agent 异步研判并写回 `payload.assessment`；单进程内存去重，重启后会对未处理告警做一次补判。
- 演示前建议按顺序走一遍：家人手机号登录（演示验证码 `123456`）→ 添加长辈并生成绑定码 → 长辈输入绑定码进入 → AI 今日简报 → 对话（含记忆引用与轨迹）→ 反诈鉴定 → 角色演练 → 记忆访谈/故事依据 → 定位与围栏告警（看守护 Agent 研判）→ 家人简报与告警轨迹。家人可添加第二位长辈并在顶栏切换，验证多长辈隔离。

### 演示数据一键重置

```bash
# 在服务器项目目录执行（需要 DEMO_MODE=1）
npm run reset:demo -- --yes
```

- 会清空演示业务数据并重新写入种子（李奶奶、家人、两段药、围栏、记忆等），保留知识库与评测记录。
- 也可以调用接口：`curl -X POST -H "x-demo-reset-token: $DEMO_RESET_TOKEN" http://127.0.0.1:3200/api/admin/reset-demo`。
- `DEMO_RESET_TOKEN` 仍是默认值 `change-me` 时接口会拒绝执行；已登录的演示会话会保留，刷新页面即可看到新数据。
- 不在命令行回显真实令牌；生产令牌只保存在 `/etc/yinling/yinling.env`。

## 语音能力与 HTTPS（重要）

- **语音播报（TTS）**：HTTP / HTTPS 都可用，但部分浏览器要求先有一次点击；页面上的「朗读本页」「念给我听」都可以直接触发。
- **语音输入（ASR）**：浏览器只允许在 **HTTPS 或 localhost** 下使用麦克风。直接访问 `http://服务器IP:3200` 时，浏览器会禁用麦克风，页面会提示改用文字或 https，这是浏览器的安全限制，不是接口故障。
- **演示时的推荐做法**：在本机建立 SSH 隧道，用 localhost 打开线上服务：

```bash
ssh -L 33200:127.0.0.1:3200 root@<服务器IP>
# 本机浏览器打开 http://localhost:33200
```

- **浏览器选择**：优先 Edge。Chrome 的 Web Speech 语音识别依赖境外服务，国内网络常返回 `network` 错误；微信/QQ/钉钉等内置浏览器通常直接拒绝麦克风。
- **长期方案**：绑定域名并在 Nginx 配置 HTTPS 证书后，再用 `https://域名` 访问。现有服务器上的 Nginx 和其他服务不要随意改动，先确认端口与证书归属。
- **TTS 没有声音**：先在系统「设置 → 时间和语言 → 语音」确认安装了中文语音包，并检查系统音量；浏览器首次自动播报被拦截时，点一下页面或「朗读本页」即可解锁。

## 反向代理（可选）

生产环境建议在 Nginx / Caddy 后启用 HTTPS。SSE 与 WebSocket 需要关闭缓冲并支持升级。

```nginx
server {
  listen 443 ssl http2;
  server_name example.com;

  location / {
    proxy_pass http://127.0.0.1:3200;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location /api/agent/chat {
    proxy_pass http://127.0.0.1:3200;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
    add_header X-Accel-Buffering no;
  }

  location /ws {
    proxy_pass http://127.0.0.1:3200;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 300s;
  }
}
```

设置 `APP_BASE_URL=https://example.com`、`TRUST_PROXY=1`、`COOKIE_SECURE=1`，并确保 `SESSION_SECRET` 足够长且只保存在服务器配置文件中。服务端每 30 秒发送 WebSocket ping，代理的 `proxy_read_timeout` 不应低于该值。

## 数据目录与上传文件

- systemd 部署：`/var/lib/yinling/data`（`master.key` 等）与 `/var/lib/yinling/public/uploads`（上传图片），由服务用户 `yinling` 独占写入。
- Compose：`app-data` 对应 `/app/data`，`app-public` 对应上传目录，`mysql-data` 保存 MySQL 数据。
- 升级前先执行 `bash deploy.sh backup`（或依赖部署时自动备份）；不要直接删除 `/var/lib/yinling` 与 MySQL 数据目录。
- MySQL 仅监听 `127.0.0.1`，不要在安全组放行 3306。

## 数字人（可选）

DH_live 数字人服务是独立的 Python 进程，不包含在本项目内。未启动时，前端会使用浏览器语音与静态头像，不影响其他功能。需要展示数字人时：

1. 按 DH_live 文档启动其 Web 服务；
2. 通过 Nginx 将 `/dh-live-api/` 与 `/dh-live-static/` 转发到该服务；
3. 或仅在演示机本地运行 DH_live，生产环境使用默认降级方案。
