# AI 评测报告与复现说明

> 目标：把「反诈判断是否准、引文是否真、故事是否忠于口述、Agent 是否会调用工具并按轨迹决策」
> 变成可重复执行、可留痕的指标，而不是只靠演示时的人工感觉。评测结果写入 SQLite 的
> `eval_cases` / `eval_runs`。

## 1. 运行方式

```bash
# 全部用例（默认 Mock 或 .env 中配置的真实模型）
npm run eval

# 只跑某一个模块
npm run eval -- --module=scam
npm run eval -- --module=story
npm run eval -- --module=agent

# 机器可读输出
npm run eval -- --json
```

- 默认通过率低于 `EVAL_MIN_PASS`（默认 80）时进程返回非 0。
- 评测会复用 `apps/api/.env` 的模型配置；`LLM_MOCK=1` 时使用确定性 Mock，适合 CI。
- 每次运行都会写入一条 `eval_runs` 记录，报告 JSON 可直接作为比赛材料附件。
- 故事与 Agent 评测使用独立的内存数据库，不会污染演示库的记忆、故事与决策轨迹。

## 2. 用例设计

### 2.1 反诈（`module = scam`）

| ID | 场景 | 期望风险 | 期望类型 | 关键证据（任一） |
| --- | --- | --- | --- | --- |
| scam_police | 冒充公检法要求转安全账户 | high | impersonate_police | 安全账户 / 转账 |
| scam_investment | 稳赚不赔、提现前充值 | high | investment | 稳赚不赔 / 保证金 |
| scam_health | 根治高血压、买二送一 | high | health_product | 根治 / 药 |
| scam_prize | 先交税费才能领奖 | high | prize | 中奖 / 税费 |
| scam_part_time | 刷单返利、先垫付 | high | part_time | 刷单 / 垫付 |
| scam_customer_service | 订单异常、点链接退款 | medium | customer_service | 链接 / 客服 |
| scam_loan | 无抵押、先交手续费 | medium | loan | 贷款 / 手续费 |
| scam_normal | 去菜市场、看邻居 | unknown | other | — |

判定条件：

1. 风险等级与期望一致；
2. 类型与期望一致（若用例声明）；
3. 结果中出现任一关键证据；
4. **所有可疑点引文必须逐字出现在输入原文中**（只做空白归一化，不允许模型改写）。

### 2.2 故事（`module = story`）

三个口述样本：苏州河边捉鱼、纺织厂第一天、一家人的年夜饭。每个样本包含标题、摘要与
两轮问答式 transcript。

判定条件：

1. 生成结果带 `fidelity` 元数据；
2. 用词重合度不低于 40%；
3. 至少 1 处原文引语通过逐字回查；
4. 被判定为编造的引号内容必须已经去掉引号，不能以「长辈原话」的形式留在正文里。

### 2.3 Agent 轨迹（`module = agent`）

四个任务：生成今日简报、电子围栏越界研判、转账冷静期研判、位置长时间未更新研判。
每个用例在独立的内存数据库中运行完整 `AgentRuntime`（计划 → 只读工具 → 结构化决策 → 写入轨迹），
工具结果是固定桩数据，模型使用 Mock 或真实 Provider。

判定条件：

1. 决策摘要非空，且告警任务至少给出一个建议动作；
2. 必选工具全部被实际调用（简报必须查用药、天气、记忆画像；围栏/冷静期必须查位置等）；
3. 声明的风险等级与升级方式一致（如 critical → high + family，info → low + none）；
4. 简报任务产出 `briefItems`；
5. 轨迹同时包含 `plan`、`tool_result`、`decision` 三类步骤。

## 3. 指标定义

| 指标 | 含义 |
| --- | --- |
| `passRate` | 用例通过率（本条用例所有条件都满足才算通过） |
| `riskAccuracyPct` | 风险等级判断正确的比例 |
| `typeAccuracyPct` | 诈骗类型判断正确的比例 |
| `quoteFaithfulnessPct` | 可疑点引文中，逐字出现在原文里的比例 |
| `avgConfidence` | 平均置信度（仅反映模型/规则输出，不等于真实准确率） |
| `llmUsedPct` | 成功走「规则 + 模型」链路的比例；失败回退规则也计入未使用 |
| `avgGroundingPct` | 故事正文与口述原文的 2-gram 用词重合度均值 |
| `verifiedQuotes` | 通过逐字回查的原文引语总数 |
| `fabricatedQuotes` | 模型生成但原文中不存在的引号内容数量（安全护栏会去掉引号） |
| `safeQuoteRatePct` | 没有出现编造引号的故事比例 |
| `aiUsedPct` | 故事实际使用模型润色的比例；回退规则稿不计入 |
| `taskSuccessPct` | Agent 任务完成率（摘要、必选工具、决策、轨迹全部达标） |
| `toolCoveragePct` | 用例声明的必选工具中，被实际调用的比例 |
| `riskAccuracyPct`（agent） | Agent 决策风险等级与期望一致的比例 |
| `escalationAccuracyPct` | 升级方式（none/family/emergency）与期望一致的比例 |
| `traceCompletenessPct` | 同时具备计划、工具结果、决策三类步骤的轨迹比例 |
| `avgToolCalls` / `avgSteps` | 每个任务平均工具调用数 / 平均轨迹步数，用于观察是否“空转” |

> `groundingPct` 是基于中文 2-gram 的词面重合启发式，只用来说明「正文有多少用词来自口述」，
> 不能替代人工事实核对。故事页与导出纪念册会明确标注这一点。

## 4. 当前基线（2026-10-28，Mock 模式）

| 模块 | 用例 | 通过 | 通过率 | 关键指标 |
| --- | --- | --- | --- | --- |
| 反诈 | 8 | 8 | 100% | 风险/类型准确率 100%，引文忠实度 100% |
| 故事 | 3 | 3 | 100% | 平均用词重合度 65%，原文引语 3 处，编造引号 0 |
| Agent | 4 | 4 | 100% | 任务完成/工具覆盖/风险/升级/轨迹完整度均 100%，平均 4 次工具、10 步轨迹 |
| 总体 | 15 | 15 | 100% | — |

这次运行写入 `eval_runs`，Mock 结果用于验证「链路、Schema、护栏、轨迹」可复现；
真实模型的效果需在配置 Key 后重新运行，并以新记录为准。

## 5. 真实模型评测注意事项

- 建议先跑 `npm run eval -- --module=scam`，再跑 `--module=story`、`--module=agent`，便于定位是判断问题、文风问题还是工具/轨迹问题。
- 真实模型输出存在波动，单次失败先看 `failures[].reasons`；若引文忠实度低于 90%，
  优先收紧提示词或降低温度，不要直接放宽校验。
- 故事评测的 `fabricatedQuotes > 0` 不代表最终正文不安全：护栏已去掉引号；它反映的是模型可靠性，
  应结合 `safeQuoteRatePct` 一起看。
- Agent 评测若 `toolCoveragePct` 下降，先检查计划提示词与工具描述；若轨迹完整但风险判断偏离，
  再检查决策提示词，避免把“工具没调”误判成“模型不会判断”。
- 评测用例位于 `apps/api/src/services/eval.ts`，修改后会自动 upsert 到 `eval_cases`，历史运行仍保留在
  `eval_runs` 中，可对比前后版本。
