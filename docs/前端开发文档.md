# 银龄守护 · 前端开发文档

> 版本：v0.1（2026-10-21）
> 适用：`frontend`（React 18 + Vite 6 + TypeScript）
> 文档关系：产品/总体架构看《开发设计文档》；接口字段看《接口契约》。本文件只写前端实现。

---

## 1. 范围与目标

### 1.1 前端负责什么

- 三端界面：长辈端、家人端、机构端（P1）。
- AI 交互：流式回答、工具调用过程、引用、确认弹窗、错误兜底。
- 多模态输入：语音、拍照/上传、粘贴截图。
- 安全交互：反诈结果、冷静期倒计时、家人确认、围栏、寻人海报。
- 记忆交互：访谈、故事时间轴、章节朗读、家人批注、导出。
- 适老化与无障碍：大字号、高对比、语音优先、少层级。

### 1.2 前端不负责什么

- 不直接调用模型/地图服务端 Key；不接触 Prompt。
- 不做最终权限校验（后端强制拦截）。
- 不做真实转账/拨号；只做提示、确认和 `tel:` 跳转。
- 不做 AI 结果的事实判断；只负责展示、引用和风险标识。

### 1.3 P0 页面

长辈陪伴屏（`/elder`）、今日简报、Agent 对话、饮食、记忆列表/访谈/章节、用药、安心守护首页/反诈/位置/一键回家、家人概览/告警/确认/健康档案/记忆、设置。

## 2. 技术栈与工程约定

| 项 | 约定 |
|---|---|
| 框架 | React 18 + Vite 6 + TypeScript strict |
| 路由 | react-router-dom 6 |
| 样式 | 现有 `styles.css` + `token.css`，不引入 Tailwind/组件库 |
| 图标 | lucide-react（已有） |
| 数据 | 原生 `fetch` + 自定义 hooks；不引入 TanStack Query |
| 流式 | `fetch` + `ReadableStream` 手写 SSE 解析 |
| 地图 | 高德 JS API（动态加载）；无 Key 时降级示意图 |
| 测试 | Vitest（node 环境）+ 浏览器手工回归；Playwright 规划中 |
| 代码规范 | ESLint + Prettier（新增）；`tsc --noEmit` 必须通过 |
| 环境变量 | `VITE_API_BASE_URL`、`VITE_USE_MOCKS`、`VITE_AMAP_JS_KEY` |

**约束：**

- 不新增重型依赖；新增依赖需说明体积和替代方案。
- 所有 API 类型来自 `@eha/shared`，不在前端重复定义。
- 所有用户可见文案走统一文案表（见 §14），不散落在组件里。
- 长辈端禁止使用小于 16px 的文字；主按钮 ≥ 64px。

## 4. 路由与角色守卫

```tsx
// routes.tsx 伪代码
<Routes>
  <Route path="/" element={<RoleSelectPage />} />
  <Route path="/login/family" element={<FamilyLoginPage />} />  {/* 手机号 + 验证码 */}
  <Route path="/login/elder" element={<ElderJoinPage />} />     {/* 6 位绑定码 */}
  <Route element={<RequireRole role="elder"><ElderLayout /></RequireRole>}>
    <Route path="/elder" element={<KioskPage />} />          {/* 陪伴屏，独立全屏布局 */}
    <Route path="/elder/today" element={<ElderHomePage />} /> {/* 原 AI 简报首页 */}
    <Route path="/elder/chat" element={<AgentChatPage />} />
    <Route path="/elder/diet" element={<DietPage />} />
    <Route path="/elder/trace/:id" element={<AgentTracePage />} />
    <Route path="/elder/story" element={<MemoryListPage />} />
    <Route path="/elder/story/new" element={<MemoryInterviewPage />} />
    <Route path="/elder/story/:id" element={<StoryChapterPage />} />
    <Route path="/elder/meds" element={<MedicationsPage />} />
    <Route path="/elder/safety" element={<SafetyHomePage />} />
    <Route path="/elder/safety/help" element={<HelpHomePage />} />
    <Route path="/elder/safety/scam" element={<ScamCheckPage />} />
  </Route>
  <Route element={<RequireRole role="family"><FamilyLayout /></RequireRole>}>
    <Route path="/family" element={<FamilyDashboardPage />} />
    <Route path="/family/profile" element={<HealthProfilePage />} />
    <Route path="/family/elders/new" element={<AddElderPage />} /> {/* 创建长辈 + 首个绑定码 */}
    <Route path="/family/invite" element={<FamilyInvitePage />} /> {/* 当前长辈绑定码 */}
    <Route path="/family/trace/:id" element={<AgentTracePage />} />
  </Route>
  <Route path="/institution" element={<RequireRole role="institution"><InstitutionPage /></RequireRole>} />
  <Route path="/settings" element={<SettingsPage />} />
</Routes>
```

**守卫规则：**

- 未登录 → 跳 `/`，显示「请选择身份」。
- 角色不匹配 → 跳自己的首页，toast「当前身份无法访问」。
- 所有路由懒加载：`React.lazy` + `Suspense` + `LoadingSkeleton`。
- 删除旧路由：`/home/child`、`/home/adult`、`/settings/alipay-bind`。

## 5. 页面规格

> 每个页面：目标 → 布局 → 状态 → 交互 → API → 验收。

### 5.1 角色选择 `/`

**目标：** 让用户 5 秒内分清「家人」和「长辈」两个入口。

**布局：**

```
银龄守护（大标题 + 一句话）
[家人入口：手机号登录，管理多位长辈] [长辈入口：输入 6 位绑定码]
[机构入口：即将开放（禁用）]
[DEMO_MODE 演示入口：长辈演示 / 家人演示]   ← 仅 DEMO_MODE=1
底部：隐私说明 / 开源声明
```

**交互：**

- 家人入口 → `/login/family`：手机号 + 验证码（演示环境固定 `123456`），首次登录自动建账号；无绑定长辈时跳 `/family/elders/new`。
- 长辈入口 → `/login/elder`：输入家人生成的 6 位绑定码，绑定成功后免密；支持 `?code=` 预填。
- 机构入口禁用，显示「即将开放」。
- 演示模式显示「长辈演示 / 家人演示」快捷入口，调用 `POST /api/auth/demo-login`。
- 记住上次角色（localStorage），但不自动登录。

**验收：** 家人可登录并添加长辈；长辈输入绑定码可进入；未登录访问 `/elder`、`/family` 会跳回；长辈端字体明显更大。

### 5.2 长辈陪伴屏 `/elder`

**目标：** 长辈不需要理解网站和 AI，打开就是一块“能说话、能求助”的屏。

**布局：**

```
[大时钟 + 日期]                          [给女儿报平安]
[李奶奶，下午好]
[一句话：今天有 3 次药，午饭清淡一点]
[吃药]            [防骗]
[吃饭]            [找不到家]
[        （ 按一下，和我说话 ）        ]
[我的故事]                          [更多]
```

**交互：**

- 四个瓦片分别跳 `/elder/meds`、`/elder/safety/scam?mode=transfer`、`/elder/diet`、`/elder/safety/help`。
- 中间按钮打开 `ChatPanel variant="kiosk" autoSpeak autoStartVoice`：自动开麦、回答自动播报；不支持语音的浏览器退化为文字输入。
- “给女儿报平安”调用 `POST /api/family/message`，`kind: "peace"`，成功后按钮变“已报平安”。
- 顶部数据独立加载：简报失败不影响四个按钮；用药/饮食显示“正在查看”“按身体配好了”等过程文案，不堆骨架屏。
- `/elder` 使用独立全屏布局，隐藏 A11y 浮标和底部导航；“更多”才进入原今日页。

**验收：** 375px 宽屏四个瓦片不溢出、按钮高度 ≥ 96px；无语音权限时仍有文字输入；AI 失败时四个按钮仍可用。

### 5.2.1 今日简报 `/elder/today`

**目标：** 打开就看到 AI 今天替您看过的事，再完成「说话 / 求助 / 防骗」三个动作。

**布局：**

```
[顶部：李奶奶，早上好] [语音播报开关]
[AI 今日简报：AI 已替您看过 → 摘要 / 优先级事项（现在/今天/稍后）/ 建议动作 / 换一版 / 查看依据]
[大卡片：我想说说话]      → /elder/chat
[大卡片：我找不到家了]    → /elder/safety/location?mode=sos
[大卡片：有人让我转账]    → /elder/safety/scam?mode=transfer
[小入口：我的故事] [吃药提醒] [联系家人]
[状态条：今天有 2 次用药 / 家人已连接]
```

**状态：**

- 简报加载中 → 保留静态问候卡，避免首屏空白；失败 → 回退静态卡并提供重试。
- 简报事项按 `now → today → later` 排序，最多 4 条；每条可带 `href` 动作。
- 简报有 `traceId` → 「查看依据」跳 `/elder/trace/:id`。
- 今天有未完成用药 → 卡片红色角标「2 次待吃」。
- 有未处理告警 → 顶部黄色提示条。
- 离线 → 顶部「网络未连接，部分功能不可用」。

**交互：**

- 「换一版」调用 `GET /api/agent/brief?refresh=1`，按钮进入 loading 并防止重复点击。
- 点击「我想说说话」→ 进入聊天并自动聚焦输入框；可选自动语音问候。
- 点击「我找不到家了」→ 进入位置页并弹出「通知家人」确认。
- 点击「有人让我转账」→ 进入反诈页并默认选中「转账冷静期」。
- 「联系家人」→ 一键拨号（`tel:`）或发送家人消息。

**验收：** AI 简报与三个大按钮在 375px 宽屏不溢出；按钮高度 ≥ 64px；点击区域足够；语音播报可关闭；简报失败不阻塞主操作。

### 5.3 Agent 对话 `/elder/chat`

**目标：** 让长辈用说话解决问题，让评委看见 Agent 的工具调用。

**布局：**

```
[顶部：返回 | 银龄守护 | 语音开关 | 清空]
[消息区]
  ├─ 用户气泡（文字/语音图标/图片缩略图）
  ├─ AI 气泡（流式文字）
  ├─ 工具卡片（可折叠：正在查询天气… / 已完成）
  ├─ 引用卡片（来源列表）
  └─ 风险提示条（高风险时）
[确认弹窗（高风险工具）]
[输入区：按住说话 | 输入框 | 拍照 | 发送/停止]
[快捷问题：今天天气 / 我该吃药了吗 / 这是不是骗子]
```

**状态机：**

```
idle → sending → streaming → (tool_running → streaming)*
     → confirmation_required → waiting_user → (resume | cancel)
     → done | error
```

**交互细节：**

- 发送后立即插入用户消息；显示「正在想…」三点动画。
- 收到 `tool_call` 时插入工具卡片，显示工具名 + 参数摘要 + 状态；`tool_result` 更新为完成/失败。
- 收到 `confirmation_required` 时关闭流，弹出确认弹窗；确认后带 `confirmationId` 重新请求。
- 确认弹窗支持 Esc 取消，初始焦点在“取消”，关闭后焦点回到输入框。
- 收到 `token` 追加到当前 AI 气泡；用户上滑时暂停自动滚动。
- 「停止」→ `AbortController.abort()`；保留已生成内容，显示「已停止」。
- 高风险横幅：红色/橙色 + 图标 + 文字 + 「联系家人」「拨打 96110」按钮。
- 引用卡片：`done.citations` 区分两类——记忆（`type:"memory"`）显示标题并跳转 `/elder/story`；知识来源只展示标题/域名，不自动打开不可信链接。
- 决策轨迹：`done.traceId` 存在时，AI 气泡底部显示「查看 AI 决策轨迹」→ `/elder/trace/:id`；轨迹页展示计划、工具结果、风险与建议动作，不展示原始思维链。
- 记忆画像：系统提示词会注入 `<memory_profile>` 摘要与敏感点；工具卡片支持 `get_memory_profile` 标签。
- 没有引用时不得把整理内容说成“长辈原话”；记忆引用缺失时展示“暂无口述依据”。
- 语音模式：按住说话；松开发送；识别中显示波形/「我在听」；识别失败可重试。
- 图片：拍照/上传后先显示缩略图，再随消息发送。
- 空状态：三个快捷问题 + 「您可以直接说话」。

**API：** `POST /api/agent/chat`（SSE）；`POST /api/agent/confirm` 见契约。

**验收：**

1. 正常回答首 token < 2.5s；工具调用可见；可停止。
2. 高风险确认弹窗出现，确认/取消都正确继续/结束。
3. 断网/超时显示可读错误 + 重试。
4. 语音不可用时显示「当前浏览器不支持语音，请打字」。
5. 长辈模式下文字 ≥ 18px、按钮 ≥ 48px。

### 5.4 记忆列表 `/elder/story`

**目标：** 让长辈看到「我说过的话被整理成了故事」。

**布局：**

```
[标题：我的故事] [开始新故事]
[AI 记得您：摘要 + 人物/地点标签]
[时间轴]
  1978 苏州河边的夏天   [3 张照片] [听故事]
  1985 儿子出生
  2010 退休后学昆曲
[空状态：还没有故事，点这里说说您年轻时的事]
```

**状态：** 加载骨架；空状态；错误重试；分页加载；画像加载失败不阻塞故事列表。

**交互：** 点卡片进章节；长按/菜单删除（二次确认）；「开始新故事」进访谈；画像卡展示 `people/places` 前几项，点击可回到对应记忆。

**API：** `GET /api/memory/items`、`GET /api/memory/profile`、`GET /api/memory/story/:id`。

**验收：** 时间轴按时间排序；空状态有引导；删除有确认；画像为空时不显示空卡；长辈模式卡片大。

### 5.5 记忆访谈 `/elder/story/new`

**目标：** 一次只问一个问题，长辈按着说话即可。

**布局：**

```
[进度：第 2/5 个问题] [照片提问] [动态追问]
[照片预览（可选上传）]
[AI 问题（大字，aria-live）：这张照片是在哪里拍的？]
[按住说话 / 重录 / 跳过]
[识别文字预览（可编辑）]
[下一步]
```

**交互：**

- 进入时可传 `topic` 与 `photoId`；`POST /api/memory/interview/start` 返回首问，`photoPrompt=true` 时提示“从这张照片说起”。
- 录音 → ASR → 文本预览 → 用户确认 → `POST /api/memory/interview/:id/answer`。
- `adaptive=true` 时展示“根据您刚才的回答追问”；`focus` 仅作 UI 提示（地点/人物/细节/感受/物件）。
- 支持「跳过」「不想说」；不追问敏感话题。
- `done=true` → 展示结构化记忆 `insight`（标题/摘要/时间/地点/人物/标签）→ 「保存到我的故事」；`engine=rules` 时注明“规则整理，可手动修改”。
- 失败：保留已录内容，允许重试；错误条固定在话题面板，不丢失输入。

**验收：** 5 轮可完成；可跳过；识别文本可编辑；照片提问与动态追问可见；保存后出现在时间轴；长辈模式大按钮。

**目标：** 让长辈/家人读故事、听故事、分享故事。

**布局：**

[标题 + 时间 + 标签]
[照片轮播/网格]

## 7. 状态管理与数据流

### 7.1 AuthContext

```ts
type AuthState = {
  me: Me | null;
  loading: boolean;
  login: (role: Role, elderId?: string) => Promise<void>;
  logout: () => Promise<void>;
};
```

- 启动时 `GET /api/me`；401 → 未登录。
- 登录后按角色跳转。
- 不做前端持久化 token；只依赖 Cookie。

### 7.2 AgentSessionContext

```ts
type AgentSessionState = {
  sessionId: string | null;
  messages: ChatMessage[];
  toolEvents: ToolEvent[];
  pendingConfirm: PendingConfirm | null;
  status: "idle" | "streaming" | "waiting_user" | "error";
  send: (input: SendInput) => Promise<void>;
  stop: () => void;
  confirm: (decision: "approve" | "cancel") => Promise<void>;
  reset: () => void;
};
```

- 消息与工具事件分开存；渲染时按时间线合并。
- 刷新页面用 `GET /api/agent/sessions/:id` 恢复（P1）。
- 不把流式 token 写入 localStorage（隐私）。

### 7.3 数据获取

- `lib/http.ts`：`fetch` 封装，`credentials: "include"`，统一错误、requestId。
- 页面级 hooks：`useSummary`, `useMemories`, `useMedications`, `useAlerts`。
- 简单缓存：内存 Map + 手动刷新；不引入 Query 库。
- 所有写操作成功后局部更新 + toast；失败保留用户输入。

### 7.4 RealtimeProvider（W5）

- 挂在路由外层，全站共用一个 WebSocket；地址取 `VITE_WS_URL`，留空用同源 `/ws`。
- 状态：`connected | connecting | disconnected`，用徽标展示“实时连接/连接中/已断开”。
- 断线重连：指数退避 + 抖动（约 1s/2s/4s，最多 5 次）；页面重新可见或网络恢复时立即重连；收到 `4401` 停止重连并回登录页。
- 心跳：客户端每 30 秒发送文本 `ping`，服务端回 `pong`；超时未收到则主动断开重连。
- 事件分发：`useRealtime(handler)` 订阅页面事件；全局 toast 按角色提示告警/家人确认；家人端对 `cooling_off` 不重复弹告警。
- 页面收到事件后做 350ms 防抖静默刷新，避免打断用户输入。

## 8. SSE 客户端

### 8.1 解析器

```ts
// lib/sse.ts
export async function streamSSE(
  url: string,
  body: unknown,
  onEvent: (event: string, data: any) => void,
  signal?: AbortSignal
) {
  const res = await fetch(url, {
    method: "POST",
    headers: { "content-type": "application/json", accept: "text/event-stream" },
    credentials: "include",
    body: JSON.stringify(body),
    signal
  });
  if (!res.ok || !res.body) throw await toApiError(res);

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const blocks = buffer.split("\n\n");
    buffer = blocks.pop() ?? "";
    for (const block of blocks) {
      if (block.startsWith(":")) continue; // keep-alive
      const ev = parseBlock(block); // event: xxx / data: {...}
      if (ev) onEvent(ev.event, ev.data);
    }
  }
}
```

### 8.2 事件处理

| 事件 | 前端动作 |
|---|---|
| `meta` | 记录 sessionId/requestId |
| `token` | 追加到当前 AI 消息 |
| `tool_call` | 插入工具卡片（running） |
| `tool_result` | 更新工具卡片（ok/fail + 耗时） |
| `confirmation_required` | 关闭流，弹确认框 |
| `done` | 标记完成，渲染引用/免责声明 |
| `error` | 显示错误卡片 + 重试 |

- 流结束但没收到 `done` → 视为异常，提示「回答中断，请重试」。
- 用户点停止 → abort，保留已有 token，状态标记「已停止」。

## 9. 语音与多模态

### 9.1 ASR

- 使用 `SpeechRecognition` / `webkitSpeechRecognition`；Chrome/Edge 稳定，Safari 部分支持，Firefox 不支持。
- **必须 HTTPS 或 localhost**：`http://IP:端口` 不是安全上下文，浏览器会禁用麦克风；界面会显示明确提示，用户仍可打字。
- 环境不支持 / 非安全上下文时，点击语音按钮给出原因，不静默失败；聊天面板顶部常驻提示。
- 权限：首次点击时请求；`not-allowed` / `service-not-allowed` → 提示允许麦克风或改用系统浏览器。
- 录音状态：`starting → listening → stopped/error`；显示波形/文字。
- 识别结果：完整累积多段 final，手动结束时返回已识别文本（带 450ms 收尾宽限），静音自动结束不丢内容。
- 错误区分：`permission`（权限）、`network`（Chrome 国内语音服务不可达，建议 Edge）、`no_speech`（没听到）、`insecure`（HTTP）、`unsupported`（浏览器不支持）等。
- 准确率增强：`maxAlternatives = 5`，对每个候选按置信度 + 医疗/生活/地域领域词命中打分，取最优候选；连续多段 final 合并。
- 长辈陪伴屏：打开小助手后自动开始识别，识别完成后**回填输入框并显示“已识别，请确认”**（可点“重新说”），由长辈确认后手动发送；其他页面同样先回填供确认。

### 9.2 TTS

- `speechSynthesis`；首次用户手势解锁；自动播报在用户首次交互前先排队，避免被浏览器拦截。
- 长辈模式默认自动播报；可一键关闭。
- 长文本清洗 Markdown 后按 ≤60 字分句；Chrome/Edge 每 8 秒 pause+resume 一次，规避 ~15 秒静默中断。
- 中文音色优先：`zh-CN` + 本地音色 + 常见中文音色名；语音列表变化时自动刷新。
- 音色切换：无障碍工具条“声音”下拉列出系统中文音色，选择后立即试听并写入 `localStorage`（`yl.tts.voice.v1`），后续播报沿用；可切回“系统默认”。
- 切换页面/停止按钮取消；取消后丢弃旧回调，不会“停了又冒下一句”。
- 播报失败（`not-allowed`、`audio-busy`、`synthesis-failed`）在无障碍工具条显示可操作提示。
- 数字人失败时自动降级 TTS。

### 9.3 图片

- 相机：`<input type="file" accept="image/*" capture="environment">`。
- 压缩：canvas 最长边 1600px，JPEG/WebP 0.8；原图 > 10MB 拒绝。
- 上传：`POST /api/uploads`；显示进度；失败重试。
- 截图：支持粘贴板（`paste` 事件）读取图片。
- 预览：缩略图 + 删除。

## 11. 数字人

### 11.1 两种模式

### 11.2 状态

- `ready`：显示 iframe；提供全屏/静音/返回。

### 11.3 注意

- 生产必须 HTTPS（WebCodecs）。
- 隐藏/弱化 DH_live 原生下拉框，保持品牌一致（P1）。
- 开源声明写在设置/关于页。

## 12. 适老化与无障碍

### 12.1 长辈模式

- 字号：标准 1.0 / 大 1.25 / 超大 1.5；默认大。
- 行高 ≥ 1.6；段落短；每屏一个主任务。
- 按钮 ≥ 64px 高；图标 + 文字；避免纯图标。
- 对比度 ≥ 4.5:1；风险色 + 图标 + 文字。
- 语音优先；可关闭自动播报。
- 二次确认：呼救 3 秒、转账 60 秒，均可取消。

### 12.2 无障碍

- 焦点可见；Tab 顺序合理；弹窗焦点锁定并可 Esc 关闭。
- 首个可聚焦元素是“跳到主要内容”链接，`main` 带 `id` 与 `tabIndex=-1`。
- `aria-live="polite"` 用于流式回答与访谈问题；危险 toast 用 `role="alert"`，普通 toast 用 `role="status"`。
- 图片有 alt；图标按钮有 aria-label；实时状态徽标有可读文本，不只靠颜色。
- 支持键盘操作；不依赖 hover。
- 尊重 `prefers-reduced-motion`。
- 表单错误与字段关联；不用仅颜色表达错误；移动端触控目标 ≥ 44px。

### 12.3 文案

- 不用「大模型」「RAG」「Agent」等术语；用「我帮您查」「我记下了」。
- 错误说人话 + 下一步；不显示堆栈。
- 医疗/金融必须带免责声明。

## 14. 错误处理与文案

| 场景 | 文案 |
|---|---|
| `upstream_timeout` | 网络有点慢，我再试一次。 |
| `upstream_error` | 服务暂时不可用，请稍后再试。 |
| `missing_config` | 功能还没配置好，请联系管理员。 |
| `unauthorized` | 登录过期了，请重新选择身份。 |
| `forbidden` | 当前身份无法查看这个内容。 |
| `rate_limited` | 操作太频繁，请稍等一会儿。 |
| `payload_too_large` | 文件太大了，请换一张小一点的。 |
| `unsupported_media_type` | 这个文件格式不支持。 |
| `low_confidence` | 我不太确定，建议您让家人或药师确认。 |
| `confirmation_expired` | 确认已过期，请重新发起。 |
| SSE 中断 | 回答中断了，要再试一次吗？ |
| 数字人失败 | 数字人没准备好，我直接用语音给您讲。 |
| 地图失败 | 地图加载失败，我给您列出位置和时间。 |

**原则：** 长辈端不显示错误码；家人/机构端可展开「技术详情」。

## 15. 性能

- 路由懒加载；`Suspense` + 骨架。
- DH_live wasm/视频只在数字人页加载；首屏不加载。
- 图片压缩、缩略图、`loading="lazy"`。
- 字体自托管；避免外部 CDN。
- 代码分割：vendor、map、digital-human 独立 chunk。
- 首屏目标：LCP < 2.5s（4G），CLS < 0.1，JS（不含数字人）< 300KB gzip。
- 长列表虚拟化（P1）：告警/故事超过 100 条时。
- 缓存：静态资源长缓存；API `no-store`。
