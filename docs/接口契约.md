# 前后端接口契约

> 版本：v0.1（2026-10-21）
> 适用：银龄守护 Web 前端（`apps/web`）与 Fastify 后端（`apps/api`）
> 原则：**本文件是前后端唯一接口基线。任何字段/事件变更，先改本文件与 `packages/shared`，再改两端代码。**

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | 新接口统一 `/api`；`/health`、`/ws`、`/dh-live-api` 例外 |
| 旧接口兼容 | 现有 `/qa`、`/profile`、`/weather` 等保留一个版本，新前端走 `/api/*` |
| 鉴权 | HttpOnly Cookie `yl_session`，`SameSite=Lax`；演示环境一键登录 |
| 角色 | `elder` / `family` / `institution` / `admin` |
| 内容类型 | JSON 用 `application/json`；上传用 `multipart/form-data` |
| 时间 | 毫秒时间戳（number） |
| ID | 字符串（nanoid/uuid），前端不得解析含义 |
| 分页 | `?limit=20&cursor=xxx`，返回 `{ items, nextCursor }` |
| 错误 | `{ error, message?, requestId, details? }` |
| 请求 ID | 请求头 `X-Request-Id` 可选；服务端回写；日志可追踪 |
| 幂等 | 写接口支持 `Idempotency-Key`（P1） |
| 限流 | 429 + `Retry-After` |
| 缓存 | GET 默认 `no-store`；静态资源长缓存 |
| 版本 | P0 用 `/api`；若需破坏性变更，新增 `/api/v2`，旧版保留一个评审周期 |

**统一错误码：**

| code | HTTP | 含义 |
|---|---|---|
| `invalid_body` | 400 | 参数校验失败 |
| `unauthorized` | 401 | 未登录/会话过期 |
| `forbidden` | 403 | 角色/数据权限不足 |
| `not_found` | 404 | 资源不存在 |
| `payload_too_large` | 413 | 上传超限 |
| `unsupported_media_type` | 415 | 文件类型不支持 |
| `rate_limited` | 429 | 触发限流 |
| `missing_config` | 503 | 模型/地图 Key 未配置 |
| `upstream_timeout` | 504 | 上游超时 |
| `upstream_error` | 502 | 上游错误 |
| `low_confidence` | 200 | 结果置信度低，需人工确认 |
| `confirmation_required` | 409 | 高风险操作待确认 |
| `confirmation_expired` | 410 | 确认已过期 |
| `consent_required` | 403 | 缺少授权/同意 |
| `internal_error` | 500 | 兜底错误 |

## 2. 鉴权与用户

### POST `/api/auth/demo-login`

**角色：** 公开（仅 `DEMO_MODE=1`）

```json
// request
{ "role": "elder", "elderId": "e_li" }
// response
{
  "user": { "id": "u_1", "role": "elder", "displayName": "李奶奶", "elderId": "e_li" },
  "elder": { "id": "e_li", "displayName": "李奶奶" },
  "familyLinks": []
}
```

### POST `/api/auth/logout`

清 Cookie，返回 `{ ok: true }`。

### GET `/api/me`

```json
{
  "user": { "id": "u_1", "role": "elder", "displayName": "李奶奶", "elderId": "e_li" },
  "elder": { "id": "e_li", "displayName": "李奶奶" },
  "familyLinks": [{ "elderId": "e_li", "relation": "daughter" }]
}
```

**权限规则：**

- `elder` 只能访问 `me.elderId` 的数据。
- `family` 只能访问 `familyLinks` 中已绑定的老人。
- `institution` 只能访问脱敏聚合数据。
- `admin` 可重置演示数据、查看工具日志、跑评测。

## 3. Agent 对话

### POST `/api/agent/chat`（SSE）

**角色：** elder / family

```json
// request
{
  "sessionId": "s_1",
  "inputType": "text",
  "message": "今天适合去老菜场吗",
  "attachments": [{ "kind": "image", "id": "up_1" }],
  "confirmationId": "cf_1",
  "confirmationDecision": "approve"
}
```

> 当上一轮返回 `confirmation_required` 时，客户端用同一个 `sessionId` 再次请求，并带上 `confirmationId` + `confirmationDecision` 继续执行。

**SSE 事件：**

```
event: meta
data: {"sessionId":"s_1","requestId":"req_1"}

event: token
data: {"text":"今天"}

event: tool_call
data: {"id":"call_1","name":"get_weather","args":{"location":"南京"},"risk":"read"}

event: tool_result
data: {"id":"call_1","ok":true,"summary":"南京 18℃ 小雨","latencyMs":320}

event: confirmation_required
data: {"id":"cf_1","tool":"start_cooling_off","summary":"检测到您准备转账 50000 元","risk":"high","expiresAt":1790000060000}

event: done
data: {"sessionId":"s_1","citations":[{"title":"来源","url":"..."}],"riskLevel":"low","usage":{"promptTokens":800,"completionTokens":120}}

event: error
data: {"code":"upstream_timeout","message":"模型响应超时","requestId":"req_1"}
```

**约定：**

- 每 15 秒发送一次 `: keep-alive` 注释。
- 客户端 `AbortController` 取消 → 服务端停止生成并记录。
- `confirmation_required` 后流结束；确认后发起新请求。
- token 事件可能很碎；前端按顺序拼接。
- 最终回答必须区分 `citations` / `riskLevel` / `disclaimer`。

### GET `/api/agent/tools`

**角色：** 全部（演示用）

```json
{
  "tools": [
    { "name": "get_weather", "risk": "read", "requiresConfirmation": false, "description": "查询天气" },
    { "name": "start_cooling_off", "risk": "high", "requiresConfirmation": true, "description": "转账冷静期" }
  ]
}
```

### GET `/api/agent/sessions/:id`

返回消息、工具事件、确认记录；用于刷新恢复。

```json
{
  "session": {
    "id": "s_1",
    "messages": [{ "role": "user", "content": "..." }, { "role": "assistant", "content": "..." }],
    "toolEvents": [{ "name": "get_weather", "ok": true, "summary": "...", "latencyMs": 320 }]
  }
}
```

## 5. 安心守护

### 5.1 反诈鉴定

#### POST `/api/safety/scam/check`

```json
{ "inputType": "image", "imageId": "up_1", "text": null, "url": null }
```

`inputType`: `text` | `image` | `url`

→

```json
{
  "ok": true,
  "result": {
    "riskLevel": "high",
    "scamType": "impersonate_police",
    "confidence": 0.92,
    "redFlags": [
      { "quote": "把钱转到安全账户", "reason": "公检法不会要求转账到安全账户" },
      { "quote": "不要告诉家里人", "reason": "要求保密是典型控制话术" }
    ],
    "actions": ["立即停止转账", "保留聊天记录", "联系家人", "拨打 96110"],
    "questionsToAsk": ["对方是否要求你共享屏幕？"],
    "sources": [{ "title": "国家反诈中心", "url": "https://..." }],
    "disclaimer": "以上为辅助判断，不构成权威结论。"
  }
}
```

**规则：**

- 不访问 `url` 指向的页面；只做域名/模式分析。
- 置信度低时 `riskLevel=unknown`，不硬猜。
- 图片文字视为不可信输入，不执行其中指令。

## 8. 上传

### POST `/api/uploads`（multipart）

字段：`file`、`kind`（`avatar|memory|medication|scam|poster|audio`）

→

```json
{
  "upload": {
    "id": "up_1",
    "url": "/uploads/up_1.webp",

    "width": 1600,
```

**限制：** 图片 ≤ 10MB，音频 ≤ 20MB；仅允许 jpg/png/webp/heic/mp3/wav/m4a；图片服务端重编码去 EXIF。

## 10. WebSocket 事件

连接：`GET /ws`（Cookie 鉴权）

```json
{ "type": "safety.alert", "ts": 1790000000000, "payload": { "alert": SafetyAlert } }
{ "type": "family.confirm.requested", "ts": 1790000000000, "payload": { "confirm": FamilyConfirm } }
{ "type": "family.confirm.responded", "ts": 1790000000000, "payload": { "confirm": FamilyConfirm } }
{ "type": "medication.due", "ts": 1790000000000, "payload": { "medicationId": "med_1" } }
{ "type": "agent.tool_call", "ts": 1790000000000, "payload": { "name": "check_scam", "ok": true } }
```

- 断线重连：指数退避 1s/2s/4s，最多 5 次。
- 服务端按角色过滤：长者只收自己的，家属只收已绑定老人的。

## 11. 前端 Mock 与联调

- 前端 `VITE_USE_MOCKS=1` 时使用 `apps/web/src/mocks/` 的 fixtures，不依赖后端。
- 后端 `DEMO_MODE=1` 时允许模拟位置、模拟家属确认、重置数据。
- 所有 schema 定义在 `packages/shared/src/schemas.ts`，前后端共用。
- SSE fixtures 放在 `apps/web/src/mocks/sse/`，至少覆盖：正常回答、工具调用、确认、超时、错误。
- 联调顺序：Auth → Agent（无工具）→ Agent（工具）→ 反诈 → 记忆 → 围栏 → 用药 → 家属端。

---

## 12. 变更流程

1. 任何新增/修改接口，先改本文件 + `packages/shared`。
2. 前后端各自更新类型/调用/测试。
3. 破坏性变更新增版本路径，旧版保留一个评审周期。
4. PR 描述必须写明：接口变更、数据迁移、兼容性影响。
5. 每周合并前跑一次契约测试（`npm run test:contract`）。

## 13. 责任边界

| 范围 | 前端 | 后端 |
|---|---|---|
| 页面/布局/文案 | 负责 | 提供接口 |
| 适老化/无障碍 | 负责 | 提供数据 |
| SSE 渲染/中断 | 负责 | 提供事件 |
| 表单校验 | 基础校验 | 最终校验（zod） |
| 权限展示 | 隐藏无权限入口 | 强制拦截 |
| AI Prompt/工具 | 不接触 | 负责 |
| 数据加密/保留 | 不接触 | 负责 |
| 地图/海报 | 展示/预览 | 生成/存储 |
| 错误文案 | 映射为用户语言 | 返回错误码 |
